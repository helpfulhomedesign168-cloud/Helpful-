## 1.2 頁面與建立流程

客戶列表：姓名／電話／WhatsApp／授權證件查詢、地址摘要、相關授權單據；詳情分基本資料、住宅、授權來源及附件。Sales主要入口「建立報價」→查客戶→選既有或輸入新資料；不提供只建客戶後不配報價的Sales快捷。

報價工作頁：客戶／住宅區→逐項工程卡→選項／現場備註與圖→價格摘要→版本／簽署→款期跟進。手機直向卡片，Pad可左右區，計價即時顯示但後端正式驗證。

未完成客戶／工程必填可存草稿，不能提交；因此草稿不強制先保存完整正式Customer。模板可完全沒有客戶資料。

## 1.3 報價明細與狀態

明細必存：line_id、service_item及規則版本、次序／位置、真實尺寸／單位／數量、計費量／低消結果、選款值／待選政策、客戶與內部備註、現場附件、折扣前／後額、執行方式及成本快照。允許同項目多條，彈「已存在同項目，是否新增另一項？」；不同房間／廁所／門各自記錄，不簡單合成數量2。

狀態：草稿→待客戶確認→已簽／待首期或轉Invoice→已轉Invoice。另待補資料／待問價、客戶拒絕／已取消／封存。拒絕單保留、可Archive，不能硬刪或直接複製成新報價。Template可合法重用工程結構，不以取消原單複製替代。

正式接受只用**客戶簽名指定報價版本**；WhatsApp文字／截圖、電話不接受。保存原籤檔、version_id、實際簽日、上載人／時間。Phase1支援上載紙本簽署掃描／相片，不假設已選定電子簽章平臺。

未轉Invoice改內容：新版本＋修改原因＋重新簽；轉後用Module05。原明示同價待選首次補選是唯一獨立確認附件例外，不覆寫原簽署快照。

## 1.4 版本與Template

每Version保存完整客戶／地址／明細、價／成本規則、折扣、成交額、簽署／包含系列與待選狀態、修改人／時／原因。舊版只讀。

個人Template存工程組合／次序／可重用結構，不存客戶、地址、證件、附件、簽名、付款、Invoice或選款確認；預設款式不視作新客戶已確認。本人私有，多份；主管／Admin不能因大Scope看他人Template。分享給有效內部帳號，接受後獨立副本，不即時共編。收件人支持有效Email，亦可用員工ID／姓名最小查找。套用生成新草稿，使用現在有效規則，停用／缺規則必補再提交。

## 2.2 動態欄位

文字、長文、數字、長闊高／面積、單位、單／多選、圖片、是非、附件及受支持自動欄。條件顯示可用簡單AND／OR；模板field_id穩定，舊單保留schema版本。計價必需尺寸／數量／價格級別必先完整；同價具體顏色可訂料前確認。規則不得循環、必填不能永遠隱藏。

例：批盪要位置與尺數；PD門要套數／必要尺寸／門款色／配件；地櫃要直呎／木紋／石英石。未選同價款不阻報價，但有價級未定不能猜。

## 2.3 計算次序及公式

```text
真實尺寸／量 → 換算 → 按該項計費進位 → 低消／區間／超額／套餐
→ 明細折扣前金額P_i → 全單P → 全單折扣d → 成交額C及明細分攤C_i
→ 工程參考成本E、基本佣金Q → 全單覆蓋檢查
```

固定單價×件／套；單位價×計費量。最低量用max(計費量,min_qty)，最低額再max(算價,min_amount)；兩者都有時按此明示預設，須目錄確有此配置，不能替Excel猜。尺寸超額＝base＋max(actual−included,0)×extra_rate。區間整段或累進明確設定，邊界不可重疊／漏值。

**先低消後折扣，折後低於低消允許。**範圍大於最低量不能硬選低消價；小於則按低消計費。逐條／同項目合計由每Service Item設定，不全公司一律。羣組價按穩定明細分攤，記真實量與計費量，不把低消量當採購量。跨主／補的低消合併未定，暫不能自動跨來源合計。

各項可設定整呎／半呎／精確小數／公司自訂邊界；不能一律向上或四捨五入。未有規則的項目不發布。單位換算保存原輸入，例如inch／foot倍率12，面積轉換須平方，不把15寸×96寸當15呎×96呎。多段／不同房間可多明細，不能用同項目名稱推定合併。

金額Decimal兩位；尺寸精度獨立。全單折扣係數精確判d<0.95。不支持Sales任意單項改價／固定減免輸入。技術尾差見14章。

## 2.4 成本模式與全單保護（已確認）

| 模式     | 參考成本E                            | 實際費用來源                                            |
| -------- | ------------------------------------ | ------------------------------------------------------- |
| 外判比例 | 該項折後C_i×60%                      | 判頭有效淨應付＋公司供料費用；扣料由會計核實            |
| 固定服務 | Admin設定固定成本，不隨d減少         | 供應商有效服務費用替代該組件預算                        |
| 公司自營 | 材料／服務參價＋人工預算＋適用直接費 | 有效Bill＋會計人工分配＋直接費用，不付該項60%給一般判頭 |
| 待確認   | 缺規則不當0                          | 草稿／補設定；不顯確定盈利                              |

固定出街6000與成本5000，95折成交5700成本仍5000。固定出街價仍參與全單折扣，執行／成本與售價模式分開。

```text
S = C − E − Q
Q = 該主／補來源的預計基本佣金合計（標準12%，低於95折9%）
```

E／Q完整且S<0不可提交；單項不足只提示，全單達標可提交。S=0可提交但警示為設計預設，不自造最低利潤率。未知成本不可假0；同價未選有有效保守成本基準可報，預設採合法包含系列可選成本上限。外判預算採完整60%，不提前算將來1.1扣料行政差額為可用利潤。

低於95折Sales可自行提交，線下同主管商量，系統提示減傭但無線上必批。仍受完整資料／全單保護。公司禁止亂報虧損，不代表系統有已確認8折／9折數字下限；不得新造。Bonus／租金／行政未納入S，**S不是淨利潤**。

已成交後保留原預算，用PO／Bill／人工替代對應組件更新預測，不反改簽價、不自動補收／扣薪／停工或減傭。實際價可由CS接受，偏差留原因，必要有權會計／Admin核對。

# Module 03：Invoice、期款及正式收據

## 3.1 統一付款方案

| 單筆有效折後成交C | 首期 | 中段 |    約80% |
| ----------------- | ---: | ---: | -------: |
| 0<C≤100000        |  50% |  50% | 無第三期 |
| C>100000          |  30% |  30% |      40% |

主／每正數補單各自判C，包括剛好100000用50／50；不合計主補決方案、不按折前額。首期成立纔可安排。中段一般泥水＋油漆約40–50%，CS按該組實際工序確認，不自動依日期／百分比。

Invoice是應收文件，付款記錄是事實，Receipt是有效足額期款證明；三者不互相取代。**先收首期再轉Invoice**是公司本系統規則，不因會計軟件習慣反改。

## 3.2 成交／開單原子流程

有效指定簽署版＋會計已核足首期＋Team／Sales／主管與代號齊→開單員核對→後端一次轉主Invoice及WorkOrder，或補Invoice及原工程Group。Invoice完全來自有效簽版，開單員不自由輸入總額／項目／折扣。缺條件不強開，重試／兩人操作只出一Invoice。

開單員確認指讀取財務結果及出單核對，不代會計銀行核實。Admin替補亦守條件；Finance兼任須獨立Grant。

## 3.3 付款紀錄與誠意金

每筆payment_id、來源quote／change／invoice（轉前可空Invoice）、類型／期數、金額幣別、實際收款日／有效日、方式、交易參考、收款人／保管人、證據、Sales確認／時、Finance核對／時、Allocation及備註。

方式現金／FPS／轉帳／支票，支票有號碼／銀行／存入及兌現日，**成功兌現先有效**。Sales登記／確認客戶證據≠銀行有效。

誠意金可有可無、金額非固定；獨立客戶付款且內含首期。不另收一份收入。公司通常非退還的既定描述不自造新法律條款；後減／退款人工依公司正式政策，不自動退款。

已確認效率規則：Sales保管誠意金＋會計查客戶銀行有效餘款達足首期，即可成交，不等保管款回公司。如100000首期50000，1500保管＋銀行48500即達標；銀行實際48500不能顯成50000。現金一般有效確認亦由會計留來源，不由Sales一點就開工程。

## 3.4 期款跟進／收據

CS判指定主／補組可追期→站內Office及原Sales通知→Sales聯絡／記證據→會計核有效款→開單員發該期正式收據。未收足一期不出該期正式Receipt；可有內部付款紀錄但不冒名正式收據。

首期收據顯總額、內含誠意金、其他有效付款及方式；無誠意金顯無或隱藏該欄。二／三期同理。完成後有完成結清／完成收據視圖，引用既有付款，**不新增一筆收款／收入**；完成證明與結清證明資格不同，見13章。

未付下一期不進入該組下一工序，由CS記暫停／追款，不自動取消或按未定SLA逾期；相依工序仍需CS明確判斷，不自動全工程停。

# Module 08：工程採購、收貨及埋單交接

## 8.1 PO建立／正式發出

**一PO只屬一工程＋一供應商**，可含合法主補明細但保留分配。CS主力建及發一般PO，Admin可授合法替補，不加所有採購老闆必批。CS可接受本次實際價與參價不同，留原因／約定；不能修改Catalog參價／已簽客戶價。

## 8.3 配送及補貨的精簡範圍

各供應商自行負責運輸配送；若另向公司收費，公司承擔，**不扣判頭、不納物料×1.1基數**。商品單價本包配送未拆項就保存約定價，不憑空估運費；明確另列不能塞進物料基數。

不建常規分批收貨、逐批扣料、逐箱進度／跨工程運費引擎。偶發分批由供應商處理，CS原PO備註，未齊仍待問題處理，不假已收。

現場判頭／師傅線下回覆及必要圖／送貨單，CS登記，不要求現場人登入。免費補送只補貨結果，不造費用；公司付補貨則公司費用、掛原問題及PO，**不再次扣判頭**。

未發草稿可改；已發PO修訂同號新version、原文／原因／供應方約定證據／日期保留。修PO不改客戶工程／選款，取消／退款人工；無庫存退貨倉庫或自動跨月沖帳。

## 8.4 有效物料扣款及費用防重

```text
G = 指定判頭承接的比例模式明細折後合計 × 60%
M = 可扣的有效產品／物料採購費（不含另列運費）
K = 會計確認的M × 1.1
判頭淨應付 = G − K
外判範圍工程費用 = G − K + M（公司另付運費F有有效來源再加F一次）
```

PO只預計K；Finance核有效物料費、收貨／問題、Assignment歸屬才確認K。不因供應商付款次數重扣。自營及公司承擔問題補貨不產生一般判頭K。判頭已報淨額不能再減一遍K；G不再乘0.6。K>G人工異常，不自動生成負數付款／追款。

例金成承接32850，G19710，瓷磚M1900，K2090，判頭淨17620，對外費用19520。供應商與判頭兩筆付款不是額外兩份費用；190行政差額已在淨費用反映，不能再加190盈利。

一月供應商一張合併Bill可跨PO／工程分配，總Allocation等Bill有效額，只入一次；Statement若彙總既有Bill／付款只對帳不新增費用。一PO一工程與月結一Bill多工程是不同層，兼容。

# Module 10：精簡工程財務與結算

## 10.1 頁面／已定範圍

財務中心會計子頁：客戶有效收款、誠意金保管回收、供應Bill／應付、判頭結算、工程費用／人工、成本對照、佣金月結及人工例外。開單子頁的Invoice／Receipt與這些引用同來源，不重複建。

## 10.2 誠意金資金位置／批次回收

CustomerPayment一次發生，CustodyPosition是錢在Sales／主管／公司；回公司是資金移交，不新客戶付款／收入／業績。

會計可按主管WhatsApp說明建Batch：交款人、銀行金額／幣／實際入日／參考／附件、原payment_id逐客分配、已分配／差額、核對人時／狀態。例1500＋600＋2000＝4100，一銀行存款→三原款回收，不能每人都4100或重抵首期。

草稿可缺／有差異，有效確認分配總額＝銀行可用額，單款回收≤尚未交回；重導／重試一次。主管較後月份交回不改原首期月／主管歸屬。未交回列內部待回收不列客欠／凍結。公司已付滿首期Receipt不在此重發。

## 10.3 供應商Bill／應付／實付

供應付款模式多種：訂金＋餘款、到貨後、月結。本次約定為主，常見先40%之後出貨後付餘，但不強制所有PO4／6。未收貨可記錄有效約定預付款，不假驗收或提前確認扣料。

SupplierBill Header含內部ID、原單號／日期／supplier／currency／amount／file／CS來源、Finance核對；Lines／Allocation對PO／line／group／purpose，費用類別材料／服務／另列運費。確認後應付、預付可用／核銷、已付、尚欠分開。Payment記錄實際線下支付、date／幣／額／方式／參考／証據／對方／經手；按鈕不轉銀行錢。

HKD／CNY各自保存，HKD成本對照由會計填來源／日期／換算額；未確認不能1:1合計或當0。Admin有HKD有效成本預算可正常報價，無需實時匯率。

月底合併Bill分配守恆、Statement匹配既有收費；賬單費用、PO承諾、付款不是多筆成本。退款／貸項／退貨線下人工記調來源，不自動衝回。

## 10.4 判頭完工逐工程一次結算

不開工預付、不施工分期。完成後判頭WhatsApp報實收→CS核承接範圍／有效折後額／60%／供料預計及判頭報的是G或淨額、核完工證據→交會計→核有效K／差異→逐工程一次付款，無常規留尾款。若同工程多個判頭，每位自己有效承接範圍一結算來源，不分整工程60%給每人。

字段settlement_id／work_order／contractor／assignment_lines、來源主補及成交快照、G、可扣M／K、判頭報額／gross_or_net、CS核額／說明／附件／日、Finance核K／淨應付、已付／付款來源／狀態。差異退回人手核對，不改客戶Invoice或猜報額。已報淨款用系統比對一次，不再減K。

付款不強制等客戶最後期到賬才處理判頭，未作此業務批准。訂料付費與判頭付款不同。

## 10.5 自營人工與費用對照

公司師傅日工、可同日2–3單，排工不自動多算日薪。Finance手填有效人工費用來源與工程Allocation，總分配≤原額，未分配顯示缺項，不假0。實付人工不再加一份費用。

報價原預算不可改；預測用有效PO／未實現預算；已核費用用Finance有效Bill／判頭淨結算／人工／直接費。一個組件費用實現只替代其預算，不預算＋Bill＋Payment再加。

例自營材料2000＋人工預算1500＝3500；Bill2000只替材料；後來分配人工500則成本2500，不再加1500或各單一天人工。外判範圍G−K＋M；另運F公司費一次。費用齊才顯示C−E_actual−Q_effective「工程直接費及基本佣金後差額」，未計Bonus／營業成本，不能稱淨利潤。應付尚欠與差額另列。

## 10.6 人工例外／平臺接口預留

Refund／減款／退票／跨月／缺歸屬等錄原source、事實／證據、線下決定、金額幣／必要前後、經手／時間、外部文件／reference、待人工／已記錄。不無痕改舊有效款；已結月不自動重開或扣薪。

未來會計接口external_system／tenant／external_id／version／sync_state／idempotency及last_error，僅預留。當啓用另定唯一正式帳務來源及必要狀態回傳，不讓兩邊自由改同金額；傳必要contact／invoice／fee／付款結果，不把施工備註或證件搬到平臺。

## 12.1 ID登入與建帳

**員工login_id＋密碼**，不是長Email。Admin自訂、公司唯一、大小寫不敏感／trim；設計預設3–20位英數字加\_-，停用ID不另分配。account_id系統永久不變、Sales／主管業務代號獨立，不能拆Login ID計傭。Email選填有填規範化唯一，Template分享可用ID或Email。Phase1所有角色只員工ID＋密碼，無強制驗證器／SMS／Email OTP，第二重驗證後期。此選擇不取消安全設密碼、節流、session撤權與敏感資料權限；詳細預設見附錄C。

Admin建姓名／Login ID／選填Email→崗位角色→Sales Team／階層及代號→資料Scope／字段動作預覽→保存／一次性安全設密碼→本人Dashboard。同賬號桌面手機共數據；無公開註冊選Admin，員工不能自改Team／Role／業務碼。Admin只能重設不讀原密碼，無Email可一次性鏈接現有內部渠道交付，不寫日誌。

## 12.2 權限三層

Account有效＋**Action（做甚麼）＋Scope（哪些來源）＋Field／File（哪些欄／文件）**＋業務資格同時後端通過。先選Sales／CS／開單／Finance等角色模板，再選本人／指定Team／多Team／公司，不因全司Scope開所有成本／薪資。

普通Sales本人；主管授權B、阿頭授權A/B只讀營運。Office各自己部門源，不是Office就全開。private Template、他人薪酬、完整證件／原簽PDF獨立控制。CS永不默認原報價，Finance只財務必要投影；附錄A逐動作為準。

兼任按每完整RoleGrant action+scope+fields判定，不能把Sales寫權與Finance公司Scope拼成寫他人單。模板修改有前後差異及影響用戶預覽，個別Grant不改全模板。停用／撤權後續API即失效，歷史不刪；Admin不能停最後有效Admin致失管，不能追已下載文件。

## 13.3 所有生成文件共用框架

A4直向多頁、繁體中文，Logo／公司名→文件類型／號碼／版本／日期／頁碼→客戶或對方＋來源→明細→金額／期款摘要→適用原公司條款／簽名（按類型）→版本／產生者追蹤。

已收到公司抬頭：好幫手家居裝修設計有限公司／HELPFUL HOME DESIGN LIMITED，以及藍橙橫向Logo。使用原圖保持比例，不AI重畫；開發時配公司Logo資產。舊照片印「收據」及D6000344_R1，不據此改新Invoice格式或首期比例。舊條款不可減項與新版未施工可提出取消等差異需公司核對，不直接照抄發布。真實客戶資料及手寫成本／人員不當Demo seed。

- 長明細自動換頁，重複表頭、頁碼N/M，避免總額及簽名被裁；同一明細可延續但不可漏尺寸／待選說明。
- 版面簡潔；內部施工長文不把客戶版變天書。對成交範圍有實質影響的材料級別／不包括承諾應用Admin客戶白名單短文表達，不能因簡潔把條件全部隱藏。
- 客戶可見備註與內部備註兩欄，不自由拼接。公開圖只款式必要縮圖，不原廠PDF。
- 未完整資料可內部預覽「草稿／不可正式使用」。公司條款／付款資料未配置時開發可跑Demo，但**正式對外匯出須提示缺公司設定**，不以AI寫新條款補齊。
- 正式文件無假資料；原型清楚「示例」。生成文件不是代客簽名，簽名空區與上載實際已簽檔分開。

## 13.6 Invoice樣板

invoice_id／no、主／補標記、issue_at、有效來源Q/CQ號／V（顯號不提供CS原PDF權）、客戶／地址／Sales業務碼、完整客戶簡潔明細、P／d／C及固定已簽付款方案；主Invoice關聯補單，補Invoice必印「原主Invoice：……」。收款銀行／FPS說明必來Admin正式配置。

**金額與指定簽署版逐分一致**，不是隻開首期數。已收及尚欠快照／截至日可顯，但變動收款查詢另工作區；已發原PDF不可因後來收錢無聲更新。不得用Invoice替Receipt稱全額已付。

主／補共用Invoice月流水，不在補Invoice原號加A／B繞過已確認流水規則。

## 13.7 Receipt及完成結清文件

### 13.7.1 每期Receipt

receipt_id／no、issued_at、Invoice／主補、期數、該期要求及正式確認有效額、幣別、原付款分配及實際日期／方式／參考、內含誠意金（若有）、核對及收據發出經手資料。電話／銀行參考按必要遮罩，不曬內部保管人的資金信息。

例100000單首期50000＝誠意金1500＋已有效銀行款48500；Receipt可認首期總50000，但不得聲稱銀行收50000。餘下期款讀該Invoice自己的計劃。不收足不發，重下載同收據不新增收款／流水。

技術預設一Invoice＋一期一份有效正式Receipt；若當期需要重出更正文書，原號／版本留痕，財務調整仍由原核對而不是改文件湊足。

### 13.7.2 完成收據／結清摘要

本版設計用獨立CC文件，只摘要原有效Invoice、期款Receipt號／實際款及當前結清，標「本文件未新增收款」。資格CS確認完成＋財務有效應收零欠（正式調整若有必有來源）；沒有收款仍欠可出**內部工程完成紀錄**，不能標已結清。

公司想叫「完成收據」可在樣板標題設定，但底層不是新Payment／CashReceipt。晚補單仍跟自己付款／進度，不因為主完工文書關掉有效待辦。

## 13.8 選款確認單樣板

SEL號／version、客戶／地址、原Invoice（存在才顯）、原報價版／工程／明細、列表原待選field／包含系列、此次公司款式代號／名稱／圖版及公開必要規格；可只覆蓋部分待選。

示例固定說明為產品既定原則的提示文案，正式公司條款仍需公司確認：

> 本次選款只完善原報價明示的同價待選項目，不增加工程金額或改變原付款方案。未列入本次確認的待選項目仍需另行確認。

客戶簽名／日；CS核對人時只在內部／核驗metadata，不生成客戶「已核」前僞籤。原報價已定款不強制再發SEL。已選換款不重新標待選走此捷徑。

## 13.10 內部工程／外判摘要／判頭結算樣板

- **內部工程工作單：**工程號、主補來源Invoice、有效範圍／真實尺寸／選款、執行方式、Assignment／CS注意、現場／完成附件引用、各組款期資格摘要。CS不帶原報價PDF、Sales佣金或全單利潤。
- **指定判頭工作摘要：**只該Assignment明細／位置／尺寸／工種／必要施工注意／公開規格。不得附整份客戶報價；若公司線下需要告知該承接範圍價，可使用明確獲準的承接約定額，不默認附全單C。不要把「有內部成本可讀」變為對外全部輸出。
- **內部結算單：**工程＋判頭＋scope、G、M／有效K來源、gross_or_net報數／CS核數、淨應付、Finance核對、實付參考／證據、差異原因。只財務必要版；不是Invoice，不消耗Invoice流水、不再乘0.6或重複扣K。

判頭工作摘要與內部結算用Source／revision引用，不新增客戶費用或獨立工程。

## 14.2 金額、分位及總額守恆

1. 金額Decimal或整數分位，禁止binary float作正式來源。出街HKD兩位、ROUND_HALF_UP是設計預設；尺寸進位按每Service Item，完全獨立。
2. d保存精確係數，0<d≤1一般正數報價；0／負數及任意公司免費不是普通折扣。d=0.95標準，0.949999低傭，即使顯示文字95折。
3. 計出各折前P_i（含低消／已定加價）、P＝合計。C＝round(P×d,2)。折後明細精確P_i×d用**最大餘數／穩定line_id尾差預設**分配分位，C_i合計＝C。保留原量／折前及分攤機制，不能挑一條隱藏加價。
4. 最大餘數預設：先每行向下保留分位，剩餘分依未取整尾數最大者先分，同尾以line_id穩定次序；因此同輸入每次結果相同。這是全單金額尾差，不改尺寸／低消。
5. 分期前N−1期按比例ROUND_HALF_UP，最後期＝C−前期合計，總期款逐分等C。Receipt引用精確計劃／Allocation，不再各頁獨立重算。
6. Commission每角色按同C／有效率分位，Q採用同一計傭服務分項合計。身份重合按行分開後按人彙總；預算Q與有效結果相同規則，不用另外總12%精度造成不同。
7. G預設按指定承接有效比例明細C_i合計×60%分位，不要求先每項取整後不一致；保存可解釋每行拆分＋尾差。K按有效物料費source基數×1.1分位，一來源一次。
8. Cost/Payment/Bill/Batch Allocation不能超來源可用額／跨幣直接加，已核總數守恆。外幣原額與HKD確認來源分開；換算未核待核不0。
9. 計算服務輸出input_hash／rules_version／timestamp；改變實際範圍／d／價版後後端重算，不沿舊成本通過標記。Sales不能控制C／E／Q或已付值。

公司會計最終分位口徑如不同要整套一致改，不只改PDF顯示。以上為實作預設，可測試驗證，不擅稱是原Excel既定算法。

## 14.3 唯一／冪等約束最低集合

- Customer主電話規範化唯一；Account login規範化及在用／歷史業務碼規則唯一。
- source_signed_version→Invoice唯一；主Invoice→WorkOrder唯一；補Invoice→同WorkOrderGroup唯一。
- InvoiceNo／各doc展示號唯一；NumberSequence按company+type+HK month鎖／事務。
- Invoice＋期數→有效Receipt唯一；完成摘要不生現金分配。
- PaymentEvidence／BankReference只輔助查重，不以相同金額日期自動合併不同真實付款；人工確認來源＋operation防重複。
- CustomerPayment allocation≤有效款，回收Batch分配≤原保管額；同銀行回收不可重複抵客欠。
- Bill／成本／K同來源費項只有效一次；分配總額守恆，不按同PDF又新增費。
- 一source＋beneficiary＋佣金身份只一有效CommissionLine；月份／受益人／BonusType一有效結果。
- 同明細執行職責無兩有效承接；同排工operation只一次，不封合法多個真實到訪。
- WorkItem業務鍵／來源階段去重；Notification event＋recipient去重，已讀不財務完成。

## 14.4 後端授權與最小安全

全API／列表／計數／文件／Asset URL／下載／CSV／通知／cache驗證有效Grant及白名單；不能信客戶端role、Team或隱藏按鈕。CS從invoice/worksource拿施工投影，不能順FK獲取quote文件。Sales不拿cost object原JSON，主管Team只讀且他人原簽PDF／證件需獨立授權。

密碼hash／安全session／限流／登出及停用失效、一次性重設，僞造文檔編號／返回pending來源保持拒絕。敏感原件private storage與短時授權URL，來源不可匿名列目錄。Phase1只相片／文件、所有角色ID＋密碼無強制MFA；附件及session設計預設見附錄C。已選RPO≤1小時／RTO≤8小時目標，資料庫與實際附件均涵蓋；部署能力須演練驗證，不當已有保證。正式資料保存期限及供應商／技術棧仍待核，不猜法律要求。

業務更正保存actor／舊新／原因／time。編號／signed／confirmed費源不硬刪。新樣板不會覆蓋舊文件hash；私有安全圖生成保來源。只設置後臺參數不替用戶官方核款、簽署或銀行支付。

同一Customer可以關聯多單及多位有合法聯絡關係的Sales，不強制一個永久獨佔Sales owner。授權使用客戶資料不等於授權其全部舊報價／附件。

跨Sales精確電話查重可回最小「已存在」結果，不公開他人客戶完整資料；無權時請有權人員／Admin核對授權復用，不能為繞過限制另建同電話客戶。這是保守復用預設，並非每次普通查客戶都需審批。

轉Team時不自動搬走已簽來源或改歷史佣金。現有來源Team快照保持；缺歷史歸屬或特殊轉單先待人工核對，不以當前Team重算歷史。

## B.1. 全角色共用原則

Dashboard是工作入口，不建立第二套報價、工程或帳務。不重輸入原單金額、不讓通知已讀變成款項已付，不要求判頭或供應商登入。

### B.1.1 桌面與手機骨架

Sales／主管／阿頭手機：首屏保留主CTA、首兩張卡及最需處理列表，另外兩卡可展開；次級業績放較後。Pad四卡可二乘二。Office桌面可四卡一列，窄屏改兩列，不硬塞桌面寬表到手機。

列表預設一頁20項，支援翻頁；手機用卡片式列，同一權限、來源及操作，不做另一套手機資料。

主管／阿頭有「團隊營運」與「我的工作」分頁。預設團隊營運四卡，切到我的工作重用普通Sales四卡，不另發明八張同時堆滿的主卡。Team其他人的項目只讀，不冒充本人的可執行待辦。

## B.10. 空白、錯誤及行動狀態

- 成功無待辦：顯「目前沒有這類待處理事項」，可導常用入口，不虛構單據。
- 未授權：隱藏卡或顯不提供該功能，不顯示公司真實總數，也不要求擅自升權。
- 未輸入必須來源：按鈕導來源選擇；無合法來源不直接建付款／工程。
- 某卡失敗：只該卡顯示重試，其他成功結果可用；不遮整頁，不用0代失敗。
- 原來源已被處理：顯處理人／最新狀態，回列表；不能執行舊按鈕再開單／找數。
- 部門併發：記錄實際動作經手人，來源併發與冪等檢查，不增加必須認領任務步驟。
- 款項部分核對：顯示有效、待核、尚欠的區別，不把證據金額全部當已收。
- 客戶展示模式：Catalog期間不彈內部摘要；退出後恢復未讀，不取消通知。

## C.2. 技術結構與環境隔離

建議一套響應式Web應用：Sales手機／Pad及Office桌面共用業務服務，按角色呈現不同畫面。前端處理輸入及預覽，正式計價、權限、核款與出號由後端核對；關聯資料用支援事務的資料庫，圖片／PDF用私有檔案儲存。

不把Excel公式直接當程式執行；不以瀏覽器角色值、localStorage或隱藏按鈕充當正式授權。伺服器可統一計價、期款、佣金及扣料來源，UI與PDF不得各算另一套金額。

至少分**示例原型、多人測試、正式資料**。多人測試與正式資料庫／附件儲存隔離，不能因新Preview而覆蓋真實公司資料。只有示例原型可有標示Demo角色切換；正式／共享試用必須真認證。

Phase1設計預設在線使用；沒有完整離線報價、Service Worker離線證件快取或離線合併價格引擎。斷網保留當前畫面未儲存內容並明示狀態，不承諾刷新後仍保存；恢復後先驗版本及重試，不讓舊設定靜默提交。

## C.3. 員工ID登入及帳號保護

沿已確認：Admin自訂員工ID＋密碼，Email選填，無公開註冊。永久account_id與Login ID、業務代號分開。

### C.3.1 建帳及重設預設

Admin建帳並配置角色／Scope→產生一次性設密碼連結→透過既有內部渠道交付→員工自己設密碼→進本人工作台。建議連結30分鐘有效且用後失效，可重新產生並撤舊連結。重設不要求Admin讀原密碼，重設成功撤銷舊sessions。不得在日誌或匯出保存設密碼token。

密碼建議最少12字元，可用長密碼／短句；不強迫固定頻率無理由更改，疑似洩漏及重設時需更新。正式方案使用成熟安全認證及慢雜湊，不能明文保存或以普通hash冒充安全密碼儲存。

登入錯誤用中性提示，設帳號／來源節流及逐步暫停，不無限試密碼；避免固定永久鎖定讓外人可惡意鎖員工。祕密只在後端／安全環境變數，不能放GitHub或瀏覽器。

### C.3.2 Session及工作保留預設

HTTPS；session cookie具Secure／HttpOnly及適當SameSite，後端有跨站請求防護。設計預設session最長8小時、閒置60分鐘需重新驗證；可按正式使用手感再調整。停用／撤權後下一個後端請求即拒絕，不能只等session自然過期。

session再驗證不能無聲清空已成功保存草稿。表單可在輸入停頓後自動存本人草稿，顯示伺服器已確認保存的時間；存檔失敗須顯示「未儲存」及重試。附件只有後端確認上載及關聯成功才顯已完成。

不為方便把完整證件、密碼、成本物件或signed URL長期存瀏覽器。下載到用戶裝置的檔案不能由系統保證遠端收回。

### C.3.3 Phase1不強制第二重驗證（已確認2B）

所有角色，包括Admin及會計，只用員工ID＋密碼，不要求綁驗證器／SMS／Email OTP；第二重驗證留後期。安全設密碼、session撤權、登入節流、私有附件及敏感讀權仍必須落實。不能把「不做MFA」解讀成只做前端假登入。

## C.4. 權限、客戶私隱及Catalog保密

沿PRD Action＋Scope＋Field／File＋業務資格的完整授權。列表、卡數、查重、搜尋、PDF、CSV、附件及通知均由同一後端約束，不能只保護主畫面。

- Sales只取本人合法來源及安全Catalog；成本／供應商身份不回到其API、HTML、圖片名稱或文件metadata。
- 主管／阿頭只因Team營運Scope而有既定只讀權，不自動看別人薪酬、完整證件或原簽PDF。
- CS仍不可讀原報價及其簽署PDF；從Invoice及有效施工投影操作。
- 完整身份證資料／附件只按既定敏感字段Grant提供；普通列表遮罩，不因能看姓名電話就能看全部證件。
- 私有原廠圖／價目與Sales安全圖分開。先核對圖片水印、電話、網址、原廠QR及檔名；可共用安全圖，不重輸每套版本。隱藏供應身份不造假材質／品牌／產地聲明。

敏感詳細讀取／匯出記錄用途來源及經手人，但日誌不抄完整證件號、檔案內容、密碼、憑據或帶token網址。對外文件只按已定客戶／供應商白名單。

公司應在正式使用前確認收集客戶資料的用途、告知方式、必要範圍及保留政策。這不是本輪判斷法律合規或重開身份證必填業務；法律及審計保存要求由公司核對，不由AI猜年數。

## C.6. 保存、封存及匯出

### C.6.1 保存政策

正式交易來源、價格版本、生成文件及返回簽署原件留可追溯版本；不能用更新名稱、壓縮圖片或改模板覆寫舊檔。

Archive表示從常用列表隱藏，**不等於刪除**。已引用主檔只能停用或合法更正，未確定政策前不做定期硬刪正式來源。

資料保留需要分種類：正式交易／財務、客戶證件、現場圖、原廠目錄、登入日誌及暫存檔。不能一律「永久保留所有資料」，也不能因省空間設定30天刪全部。

建議技術暫存孤立上載可7天後清理，但須確認無任何報價／簽署／單據／工程引用且無進行中操作；原始正式附件不走這個清理規則。這只是暫存工程政策，不是客戶資料保存期限。

正式資料期限目前標**待公司設定**。如有審計、爭議或其他需保留原因，可記保留鎖及覆核人；正式清理須符合引用完整性、備份到期及公司政策，不讓Admin任意一鍵清空已付款工程。

### C.6.2 匯出及攜出

CSV／Excel／PDF只含該角色及選定Scope可見字段，伺服器產生安全投影；敏感資料不隱藏列後塞入檔。公司完整備份／移轉資料包不同於一般員工業務匯出，需要獨立受控維運權限與記錄，不因Admin可設角色就可任意讀銀行憑據。

正常匯出顯示篩選、截至時間、來源／版本及經手人。檔案清單附內容hash／引用，重下載不產生新收款或費用。批量下載採短效取檔及安全儲存，不提供永久匿名網址。

## C.7. 多人操作、防重及操作紀錄

編輯有版本檢查；若另一人已更新，提示查看差異／重新載入，不無聲last-write-wins。涉及價格、簽署及核費要保合法來源，不能用普通表單Save改已核結果。

發Invoice／工程、付款分配、收據、Bill／有效K及佣金均由後端唯一鍵、資料庫事務及operation idempotency控制。前端禁用按鈕只是UX輔助。

同源轉Invoice只成功一次，回傳同一Invoice／工程；PDF生成失敗重渲原版而不再出號。全公司Invoice月流水鎖定且已耗號不重用，保留缺號不以排序重排。

AuditEvent記actor_id、動作、來源ID／版、可審核字段前後值／原因及伺服器時間；敏感值以最小必要方式表示。記錄不能由一般業務操作任意改掉。核款與開單仍不同職責，不因重新提交接管別人角色。

## C.8. 備份及恢復

分開保護**關聯資料庫、實際圖片／PDF、必要部署／配置版本**。只備資料庫metadata不等於附件已備份，GitHub只有程式也不是客戶資料備份。

已確認3A：RPO≤1小時，RTO≤8小時，資料庫及實際附件都涵蓋。RPO指目標最多失去多久新資料；RTO指故障後恢復可用的目標時間。正式部署須定義計時、恢復責任及演練證據，不能當現成平臺承諾或已驗證SLA。

建議每日至少一完整／可恢復資料備份，附件新增及變更亦有對應備份／版本；技術初始滾動30日，與正式資料保存年限分開。要達已選1小時RPO，需日誌／頻密增量等成熟能力；附件副本頻率亦要同步滿足目標，不能只有資料庫一小時而附件隔天才備。

備份採不同憑據／隔離位置及受控權限，避免同一誤刪或帳號失陷連備份一起毀；加密並限制存取。詳細供應商能力與成本在部署選擇時確認，未配置不稱已有備份。

恢復後必須核對故障前實際已發Invoice／文件及流水。RPO允許部分新資料遺失，不授權把已對外使用的號碼重新分配；開發者需提出可恢復／獨立對照的發號紀錄策略並演練。無法確定已發結果時，該來源及發號保持待核對，不只還原舊NumberSequence便重新出單。

上線前必須在隔離環境演練：恢復一次資料與附件、抽查簽版／款項／Invoice流水／工程／PO／扣料／佣金、驗檔案hash及引用、重試不重建款項及號。建議之後按月抽查、按季恢復演練，使用應用／平臺原生機制，不在本次建立外部排程。

由公司指定維運負責人接故障／備份失敗及容量警報；這是維運職責，不改CS／開單／Finance的客戶業務權限。未有聯繫人前保留待設定。
