# 好幫手 Homeflow — PRD v0.13 初階流程原型

這是重新設計、可操作並共享同一來源資料的Prototype，不是十二個Module全部完成的正式系統。UI用黑白灰、大字體及統一控制尺寸；不沿用DeepSeek舊Demo。

## 運行

Node 22及pnpm 11.25。`pnpm install --frozen-lockfile`後執行`pnpm dev`；開發埠固定3000。`pnpm build`產生dist。`pnpm test`測domain，`pnpm test:e2e`測真正UI點擊鏈（先`pnpm exec playwright install chromium`及啟動dev服務）。

## 先試這條流程

| 角色      | 實際入口與操作                                                                                                  |
| --------- | --------------------------------------------------------------------------------------------------------------- |
| Sales文文 | 報價管理→建立報價→客戶／地址→新增工程及真尺寸／位置／現場備註→儲存報價。資料未齊可草稿。                        |
| Sales文文 | 報價詳情→上載已簽文件（可用明示示例檔測試）→選簽日及主管→明確勾選客戶已簽→確認；再登記首筆款→提交Office。       |
| CS        | 右上角切換角色→接單跟進見同一Q；只安全摘要，未足首期不能安排。                                                  |
| 會計      | 收款核對→核每筆款；銀行款須勾已核實入帳、支票須已兌現。保管誠意金由Finance核有效，不等交回公司。                |
| 開單員    | 單據管理→待開單→首期未足不可轉；已核足後，確認出單生成唯一Invoice及工程。                                       |
| CS        | 接單跟進→同來源安排工程，或工程管理→工程詳情；選判頭／公司師傅、勾適用明細、日子時段及備註→儲存。刷新仍有紀錄。 |

不必每次重建不同假單；右上角色選單只改當前Actor，不改資料。原型工具可明確重設Demo。Sales業績只合資格來源；Admin工程目錄支援初階四種計價及外判／固定／自營模式，並非完整可配置Catalog。

## 這輪的界線

資料在同一瀏覽器分頁localStorage（`homeflow-state-v1`），文件Blob在IndexedDB（`homeflow-files`）。**沒有跨裝置多人同步、正式員工ID登入、真正服務端ACL、銀行／Xero連線、支付或生產備份。不可輸入真實身份證、銀行或客戶資料。** 所有Demo價目／人物代號及文件均不是公司覈准正式資料。

已簽版本鎖快照；目錄後改不反改舊成交。未簽草稿遇價目更新要修改／儲存及重新上載對應檔再確認簽署。完整日期版價與Catalog同期發布仍屬後續，沒有僞裝為已完成。

已收款後改簽版本先人工核對，沒有自動搬移付款。完整產品Catalog、SEL、報價Template／分享、補單、採購／扣料、後續期款／收據、施工驗收、判頭結算、名冊維護／多日排工、帳號設定／正式權限設定、匯入天書及恢復備份尚未實作。PRD仍是這些後續功能的需求依據。

## 後續交DeepSeek

先讀`docs/PRD_v0.13.md`、`docs/PROTOTYPE_FLOW_REQUIREMENTS.md`及`docs/DEEPSEEK_HANDOFF.md`；`src/domain/engine.ts`為唯一業務動作及計價，不在React頁面再寫一套規則。將BrowserRepository替換正式API／資料庫時，要保留同一來源IDs、簽版快照、Actor權限及貫穿測試；不是僅把HTML重新畫一次。
